# Script Reader Team Sync (Firebase) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Drive storage/sync of the existing app with Firebase so a team shares clients and scripts live, with admin-managed per-client access and offline editing.

**Architecture:** A `Repo` interface hides the backend. `FirestoreRepo` is the real implementation; `MemoryRepo` is an in-memory fake used by UI tests. Edits are expressed as a pure diff between the old and new script (`diffRows`) so every write is field-level and different sections never clobber each other. Security rules enforce per-client access and are tested in the Firestore emulator. Existing pure logic (docx parser, sections, reimport, recentLocations) and the reader UI are kept.

**Tech Stack:** TypeScript, Preact, Vite, Vitest, Firebase JS SDK v11 (`firebase/app`, `firebase/auth`, `firebase/firestore` with `persistentLocalCache`), `firebase-tools` + `@firebase/rules-unit-testing` (emulator tests, needs Java 21+), existing vite-plugin-pwa, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-11-15-team-sync-design.md` (builds on `2026-11-15-script-reader-design.md`)

## Global Constraints

- Public GitHub repo: no secrets, no admin email, no personal data in code, tests, docs or workflow. Firebase web config comes only from build-time vars `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID` (GitHub repository variables).
- Firebase free tier (Spark) only; no Cloud Functions.
- Emails compared lowercased; rules require `request.auth.token.email_verified == true`.
- Only the admin (the email in `config/admin`) creates/renames/deletes clients, edits members, deletes scripts. Admin can open every client without being a member.
- All members have the same rights otherwise: add scripts, edit locations/done/splits, clear "no longer in script" entries.
- Writes are field-level; a re-import writes only new/changed/newly-orphaned sections.
- Font size and last screen stay local (localStorage). Everything from v1 that is UI behaviour (reflow, ≥44px targets, dark flowing-text, Romanian diacritics, split/merge/undo, location autosuggest) is unchanged.
- Scale assumption: ~10 users, ~20 clients, ~200 scripts, ~50 sections/script; live listeners only on the open script and the visible lists.
- The Drive code (`src/drive/`, `src/sync/`, `src/storage/db.ts`, `src/model/importLocal.ts`) is removed in Task 11, not before.

## Review Focus

- Email case and verification: a token with `Anna@X.com` must match member `anna@x.com`; an unverified email must be denied (Task 3).
- Access removed or script deleted while someone has it open or has offline edits queued: screen shows a clear notice (not a blank page or crash) and dropped edits are counted (Task 10).
- Re-import while another person ticks sections: ticks on unchanged sections survive (Task 4).
- A big script (>500 section writes) is written in chunks (Task 4).
- Sign-in popup cancelled/blocked, or signed in with no clients: friendly message, no crash (Task 5).
- Same person on two devices, offline then reconnect: no lost checkmark; pending-changes indicator clears (Task 10).

## Shared types (Task 1 creates; all later tasks use exactly these)

```ts
// src/data/types.ts  (re-exports Section, Video, ScriptDoc, ParsedVideo from ../model/types)
export interface Client { id: string; name: string; members: string[] }
export interface SectionRow { id: string; videoId: string | null; order: number; text: string; location: string | null; done: boolean; updatedAt: number; orphaned: boolean }
export interface ScriptSummary { id: string; name: string; videoCount: number; updatedAt: number }
export interface ScriptData { doc: ScriptDoc; orders: Record<string, number> }   // doc.fileId = script id
export interface SyncState { online: boolean; pending: boolean }
export type Unsub = () => void;
export type RepoError = { code: 'permission-denied' | 'not-found' | 'other'; message: string };
export interface Repo {
  isAdmin(): Promise<boolean>;
  watchClients(cb: (c: Client[]) => void, onError: (e: RepoError) => void): Unsub;
  watchScripts(clientId: string, cb: (s: ScriptSummary[]) => void, onError: (e: RepoError) => void): Unsub;
  watchScript(clientId: string, scriptId: string, cb: (d: ScriptData | null) => void, onError: (e: RepoError) => void): Unsub;
  watchRecents(clientId: string, cb: (list: string[]) => void): Unsub;
  watchSyncState(cb: (s: SyncState) => void): Unsub;
  createClient(name: string): Promise<string>;
  renameClient(id: string, name: string): Promise<void>;
  deleteClient(id: string): Promise<void>;
  setMembers(id: string, emails: string[]): Promise<void>;
  addScript(clientId: string, name: string, parsed: ParsedVideo[]): Promise<{ scriptId: string; reimported: boolean }>;
  deleteScript(clientId: string, scriptId: string): Promise<void>;
  saveScript(clientId: string, scriptId: string, before: ScriptData, after: ScriptDoc): Promise<{ droppedOnReject?: number }>;
  addRecent(clientId: string, location: string): Promise<void>;
}
export interface AuthUser { email: string; name: string }
export interface AuthApi { onUser(cb: (u: AuthUser | null) => void): Unsub; signIn(): Promise<void>; signOut(): Promise<void> }
```

Firestore layout (fixed here so tasks agree): `config/admin {email}`; `clients/{id} {name, members: string[]}`; `clients/{id}/scripts/{sid} {name, videos: {id,title}[], updatedAt}`; `clients/{id}/scripts/{sid}/sections/{secId} = SectionRow minus id`; `clients/{id}/meta/recents {list: string[]}`.

### Task 1: Pure data operations

**Files:** Create `src/data/types.ts`, `src/data/docOps.ts`; Test `src/data/docOps.test.ts`.

**Interfaces:** Produces
`flattenDoc(doc: ScriptDoc, orders: Record<string, number>): { videos: {id:string;title:string}[]; rows: SectionRow[] }` (orphans get `videoId:null, orphaned:true`),
`assembleDoc(id: string, name: string, videos: {id:string;title:string}[], rows: SectionRow[]): ScriptData` (rows sorted by `order`; unknown-videoId non-orphan rows ignored),
`assignOrders(doc: ScriptDoc, known: Record<string, number>): Record<string, number>` (known orders kept; each new section gets a value strictly between its neighbours' orders, spread evenly across a run of consecutive new sections; before first = first−1000; after last = last+1000; empty known → 1000, 2000, …; orphans use a separate run after the last live order),
`diffRows(before: SectionRow[], after: SectionRow[]): { sets: SectionRow[]; updates: { id: string; patch: Partial<Omit<SectionRow,'id'>> }[]; deletes: string[] }` (only changed fields appear in a patch; `updatedAt` always accompanies a changed field),
`chunk<T>(items: T[], size: number): T[][]`.

### Task 3: Security rules and emulator tests

**Files:** Create `firestore.rules`, `firebase.json` (firestore rules path, emulator port 8080), `vitest.emulator.config.ts` (include `test/**/*.test.ts`, node environment); Test `test/rules.test.ts`; add devDeps `firebase-tools`, `@firebase/rules-unit-testing`, `firebase`; script `"test:emulator": "firebase emulators:exec --only firestore --project demo-script-reader \"vitest run --config vitest.emulator.config.ts\""`.

**Interfaces:** Rules semantics (exact):
- `signedIn()` = auth present and `email_verified == true`; `email()` = `request.auth.token.email.lower()`.
- `isAdmin()` = signedIn and `email() == get(/databases/$(database)/documents/config/admin).data.email`.
- `config/admin`: read only if `isAdmin()`; no client writes.
- `clients/{c}`: read if admin or `email() in resource.data.members`; create/update/delete only admin (members must be a list of strings).
- Everything under `clients/{c}/**`: read/write if admin or member of `c`, **except** `delete` on `clients/{c}/scripts/{s}` (admin only).
